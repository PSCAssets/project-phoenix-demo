A Two Entry Paths — Patient Chooses at Initiation
📅
Path 1 — Scheduled
Patient picks a specific date and time slot
Step
1
Patient
Selects "Schedule Phone Call" from dashboard
Only shown if telephonic enabled for enrolled program and state
System
Loads provider calendar availability
Fetches open slots filtered by program and licensed providers
2
Patient
Selects date and time slot
Confirms phone number to call. Reviews and books.
System + M06
Appointment confirmed. Notifications scheduled.
📬 Immediate confirmation to patient + provider 🔷 M06: schedules 24hr + 1hr reminders
3
Patient
Receives 24-hour reminder
Notification: "Your phone consultation with [Provider] is tomorrow at [time]. Make sure your phone is available."
M06 Automation
🔷 24-hour automated reminder fires
Sent via in-app + email/SMS. Contains: provider name, time, confirmed phone number, program name.
4
Patient
Receives 1-hour reminder
Notification: "Your phone consultation starts in 1 hour. Be ready to receive a call at [phone number]."
M06 Automation
🔷 1-hour automated reminder fires
Final reminder with confirmed phone number. Patient should be available to receive call.
5
Provider
Calls patient at scheduled time
Provider opens patient chart in provider portal. Initiates call to confirmed phone number at appointment time.
System
Appointment status → In Progress
Provider portal marks appointment active when provider initiates call.
6
Provider
Conducts consultation and documents notes
Takes call notes, updates treatment plan, places any orders.
Provider
Publishes visit summary to patient portal
Patient notified when summary is available.
📬 Visit summary ready notification
⚡
Path 2 — Real-Time (Queue-Based)
Patient joins Master Queue for immediate provider pickup
Step
1
Patient
Selects "Real-Time Phone Call" from dashboard
Confirms phone number. Reviews estimated wait context (no defined wait time in V1.0).
System
Validates real-time telephonic is enabled for program + state
Option only shown if enabled in care product config (M04).
2
Patient
Placed in Master Patient Queue
Patient sees "In Queue" status on dashboard. Estimated wait is informational only in V1.0.
System + M06
Queue entry created. Patient visible to assigned providers.
🔷 M06: SLA clock starts at queue entry
3
Provider
Sees patient in Master Queue, selects for telephonic consult
Provider views queue filtered to their assigned programs and states. Selects patient and initiates telephonic consult.
System + M06
Provider selection triggers patient notification
⚡ Real-time alert to patient
M06 Workflow Engine sends immediate notification: "A provider has selected your consultation and will call you shortly. Please be ready to receive a call at [phone number]."
4
Patient
Receives notification and prepares for call
Patient is alerted to be available. Dashboard status changes from "In Queue" to "Provider Connecting."
M06 Automation
🔷 M06: provider call window timer starts
If provider does not call within a configurable window after selection, M06 flags for escalation review.
5
Provider
Opens patient chart and calls patient
Reviews patient health profile and history. Initiates call to confirmed phone number.
System
Status → In Progress
Queue item removed from Master Queue. Appointment status updated.
6
Provider
Conducts consultation. Documents notes and publishes visit summary.
Notification
📬 Visit summary ready notification to patient
B Post-Consultation — Shared for Both Paths
After the call ends — both scheduled and real-time paths converge
1
Provider documents and publishes visit summary to patient portal
Clinical notes, treatment plan, any orders placed. Visit summary published triggers patient notification.
2
📬 Patient notified: "Your visit summary from [Provider] is now available in your portal."
Sent via in-app + email/SMS per preferences.
3
Patient reviews visit summary. Can send follow-up message referencing the visit.
4
🔷 M06: SLA clock stopped. Consult duration logged for reporting.
Activity logged to audit trail (M12). Consult moves to History.
🔷 M06 Workflow Engine items for telephonic: Schedule appointment reminder automation (24hr, 1hr), real-time queue entry SLA clock, provider selection → patient alert trigger, provider call window timer, post-consult SLA stop. All must be captured in M06 BRD.
⚠️ Real-time path availability is configured per care product in Admin Portal (M04). Some programs may only offer scheduled telephonic — the real-time queue option only appears if enabled. Configuration matrix must be defined in the cross-functional working session.
